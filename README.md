# AURA PARFUMERIE — ecommerce starter

Стартовый проект полноценного интернет-магазина парфюмерии на Next.js, TypeScript, Prisma и PostgreSQL.

## Что включено
- Каталог и страница товара (структура App Router).
- Prisma-модели для товаров, вариантов объёма, пользователей, заказов и платежей.
- Начальные товары для демонстрации (вымышленные товары/цены — замените реальными данными).
- API для создания заказа с проверкой цен и наличия на сервере.
- Подготовка WhatsApp-ссылки с составом заказа.
- Платёжный endpoint-заготовка: подключение провайдера требует merchant-аккаунта и секретных ключей.
- Переменные окружения и инструкции для локального запуска.

## Требования
- Node.js 20+
- PostgreSQL 15+
- npm

## Запуск
1. Скопируйте `.env.example` в `.env` и укажите `DATABASE_URL`.
2. Установите зависимости: `npm install`
3. Сгенерируйте Prisma Client: `npx prisma generate`
4. Создайте таблицы: `npx prisma migrate dev --name init`
5. Заполните каталог: `npm run db:seed`
6. Запустите: `npm run dev`
7. Откройте `http://localhost:3000`

## Важные настройки
- `NEXT_PUBLIC_SITE_URL`: публичный URL сайта.
- `WHATSAPP_PHONE`: номер WhatsApp в международном формате только цифрами, например `77011234567`. Замените пример на ваш номер.
- Платёжный провайдер: выберите доступного в Казахстане провайдера и получите merchant credentials. Не храните секреты в `NEXT_PUBLIC_*`.
- Перед запуском в production добавьте авторизацию админ-панели, защиту от злоупотреблений, политику конфиденциальности, условия продажи/возврата, доставку и мониторинг.

## Платёжная интеграция
`/api/payments/create` намеренно не имитирует успешную оплату. В него нужно добавить создание платёжной сессии у выбранного провайдера, а затем отдельный webhook с проверкой подписи провайдера. Статус заказа меняется на `PAID` только после подтверждённого webhook — не на основании редиректа пользователя.

## Админ-панель
Модели базы данных подготовлены, но защищённая админ-панель — следующий этап. Не публикуйте административные endpoints без авторизации.
